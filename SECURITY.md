# Security boundary

Do not put credentials, account/order exports, private logs, real research inputs or personal paths in issues, examples or review artifacts. Keep sensitive runtime data outside a published checkout.

The toolkit has no broker adapter. The reconciliation module classifies caller-supplied fake snapshots; a decision object is not an order. Preserved strategy modules simulate local files only. Their code is not audited for production trading.

Research intake has an explicit online `run` command. Ordinary imports, configuration validation, tests and the offline example do not retrieve papers. No scheduler installer is included. The test runner blocks Python socket calls in child interpreters; it is not an operating-system firewall or a proof about arbitrary native extensions.

If a credential is ever exposed, notify its rightful owner through a private channel and revoke or rotate it at the provider. Deleting a file or rewriting history does not revoke a credential. No credential exposure was established by this candidate's reported scan.

When the repository is public and GitHub private vulnerability reporting is verified enabled, use its private "Report a vulnerability" feature on the Security Advisories page. Public issues are not private: do not disclose vulnerabilities containing secrets, credentials or private data there. If the private feature is unavailable or its status cannot be verified, do not submit sensitive details through a public channel. Source publication must stop until a genuine private alternative is approved and verified. Committing this policy does not enable GitHub's reporting feature; no reporting email or enabled configuration is asserted here.

This limited-maintenance handoff promises no response time or continuing security support. The reporting route does not establish production safety.
